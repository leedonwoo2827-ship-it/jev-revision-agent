# law-errata-jev

법령이 개정되면 **우리 교재의 어느 문장을 고쳐야 하는지** 골라내고, 수정할 확률과 그대로 둬도 되는 확률을 표로 보여 주는 정오표 도구입니다.
검토자가 HTML 화면에서 항목을 체크하고 **[반영]**을 누르면 아래 세 가지가 만들어집니다.

- 반영내역
- 반영된 원고
- 게시판에 올릴 정오표

판정은 **JEV** 방식으로 합니다. 판정 엔진은 **Codex CLI**이며, ChatGPT 계정 OAuth로 로그인해서 쓰므로 API 키가 필요 없습니다.

| 단계 | 하는 일 |
|---|---|
| **J**udge | 변경 조문이 교재의 어느 문구와 관련되는지 찾고, 영향 유형을 정합니다. 유형은 수치변경, 용어변경, 내용변경, 신설조문누락, 삭제조문잔존, 무관 중 하나입니다. |
| **E**vidence | 교재 원문, 구 조문, 신 조문을 그대로 인용합니다. |
| **V**erdict | 수정확률(`p_revise`)과 유지확률(`1 − p_revise`), 기존문구 → 수정문구 초안을 냅니다. |

> 이 저장소에는 **코드만** 올립니다. 교재 PDF, 법령 원문, 판정 결과, 반영 산출물은 `.gitignore`로 제외되어 있습니다. 대상 폴더는 `_context/`, `work/`, `output/`입니다.

## 흐름

```
_context/교재.pdf ──extract_book──▶ 장 범위 쪽별 텍스트 (예: 9장 p.386–401)
_context/law_old_*.  ─┐
_context/law_new_*.  ─┴─diff_law──▶ 변경 조문 목록 (LLM 없이 조문 단위로 비교)
                         judge_codex ──▶ Codex OAuth로 조문마다 JEV 판정, 중복 정리
                         report ──▶ output/errata_ch09.html (검토 화면)
                         [반영] ──▶ output/applied/ 반영내역 · 반영본 · 게시판 정오표
```

## 설치와 실행

| 파일 | 하는 일 |
|---|---|
| `setup.bat` | 처음 한 번만 실행합니다. 가상환경과 패키지(`pymupdf`, `pyyaml`)를 설치하고, Codex CLI가 없으면 설치합니다. 로그인이 안 되어 있으면 `codex login`을 실행하는데, 브라우저가 열리면 ChatGPT 계정으로 로그인하세요. |
| `run.bat` | **웹 콘솔**을 엽니다 (`http://127.0.0.1:8765`). 콘솔이 열려 있는 동안 검은 창을 닫지 마세요. |

Python 3.10 이상과 Node.js가 먼저 설치되어 있어야 합니다.

## 웹 콘솔

맨 위에서 장을 고른 뒤, 아래 네 단계를 순서대로 진행합니다.

**① 입력 파일**
- 칸마다 파일을 끌어다 놓거나 [선택]을 누릅니다. 파일은 `_context/`에 정해진 이름으로 저장됩니다.
- 교재 PDF는 원본 그대로 올립니다. 장 범위는 `chapters.yaml`에 적힌 쪽 수대로 자동으로 잘립니다.
- 법령은 칸이 네 개입니다: 책 기준 (구) 법률·시행령, 현행 (신) 법률·시행령.
- 법령 파일 형식은 PDF를 권장합니다. HWPX와 TXT도 받습니다. HWP(구형 바이너리)는 받지 않습니다.
- **[법제처에서 법령 받기]**를 누르면 `chapters.yaml`에 적힌 버전의 구·신 법령 네 개를 자동으로 받습니다. 받은 파일은 `.txt`로 저장되며, 같은 칸에 PDF나 HWPX가 있으면 그쪽이 먼저 쓰입니다.

**② 판정 시작**
- 추출, 조문 비교, Codex JEV 판정이 차례로 진행됩니다. 진행률과 로그가 실시간으로 보입니다.
- 조문 하나에 약 40초가 걸립니다. 이미 판정한 조문은 캐시에 남아 있어 다시 판정하지 않습니다.

**③ 검토 화면 열기**
- 수정확률과 유지확률 표가 나옵니다. 항목을 체크하거나 해제하고, 수정문구를 고친 뒤 **[반영]**을 누릅니다.
- 수정확률 60% 이상인 항목은 처음부터 체크되어 있고, 유지 항목은 기본으로 숨겨져 있습니다.
- `Evidence`를 펼치면 교재 원문과 구·신 조문 인용을 볼 수 있습니다.

**④ 반영 파일**
- 만들어진 파일을 보거나 내려받습니다. 파일은 `output/applied/`에 저장됩니다.

| 파일 | 내용 |
|---|---|
| `반영내역_<장>_<시각>.md / .csv` | 전체 항목의 반영·미반영 상태, 확률, 기존→수정, 메모 |
| `<장>_revised_<시각>.md / .html` | 반영된 원고 (HTML은 삭제·추가 부분을 표시) |
| `정오표_게시판_<장>_<시각>.html` | **회사 게시판에 올릴 파일** (반영한 항목만) |

### 다른 장 추가하기

`chapters.yaml`에 아래 내용을 담은 블록 하나를 추가하면 콘솔의 장 목록에 나타납니다.
- 쪽 범위
- 법령 파일 패턴
- `fetch_name`
- `old_version`: 책 p.11 [법령적용기준]에 적힌 법령번호와 공포일자

### 명령줄로 실행하기 (선택)

```
.venv\Scripts\python -m jev.pipeline ch09            # 판정까지
.venv\Scripts\python -m jev.apply decisions_ch09.json  # 서버 없이 받은 결정 파일 처리
```

## 구성

```
setup.bat / run.bat
chapters.yaml          장별 쪽 범위 · 법령 파일 설정
jev/extract_book.py    교재 장 추출 (+ p.11 법령적용기준 줄)
jev/extract_law.py     법령 PDF/HWPX/TXT를 조문·장 단위로 파싱 (부칙 분리, 개정 태그 무시)
jev/diff_law.py        구/신 조문 비교 → changes.json
jev/fetch_law.py       (선택) 법제처 본문 받기
jev/judge_codex.py     codex exec --output-schema 로 JEV 판정, 중복 정리, 캐시
jev/report.py          검토 HTML 생성
jev/server.py          웹 콘솔 서버 (127.0.0.1 전용: 업로드·받기·판정·검토·반영·내려받기)
jev/console.html       웹 콘솔 화면
jev/apply.py           반영 처리 (반영내역 / 반영본 / 게시판 정오표)
```

## 주의

- 확률은 Codex가 판단한 값입니다. 최종 반영 여부는 반드시 사람이 확인하세요.
- 책 쪽번호는 PDF 쪽번호와 같다고 가정합니다. 9장 교재 기준으로 확인했습니다.
- 수정문구 위치는 교재 텍스트에서 **공백을 무시하고** 찾습니다. 위치를 찾지 못한 항목은 반영내역에 "수동반영 필요"로 표시됩니다.
